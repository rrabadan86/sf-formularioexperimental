slimfit Robô · instalação

Runbook de instalação

Passo a passo para colocar o robô rodando na franquia nova — do servidor zerado até tudo no ar, usando os comandos já validados em produção. Faça depois de receber a ficha da unidade preenchida.

Ubuntu + Node 20 PM2 24/7 Xvfb (tela virtual) ≈ 1 dia de trabalho
!

Nunca copie o disco da sua VPS para a do cliente

Parece atalho, mas arrasta três coisas que não podem ir para outra unidade:

  • 🚨 A sessão do seu WhatsApp — o robô do cliente conectaria no seu número (e ele sumiria da sua VPS).
  • 🔑 O seu .env com as senhas do seu EVO, seus alertas e sua planilha.
  • 🗑️ Logs, filas de mensagens, cache do navegador e node_modules — só dão problema.

O caminho certo: clonar do GitHub → criar um .env novo → escanear o QR do WhatsApp dele → testar. Sempre na versão mais atual do código.

Antes de começar

O que ter em mãos

  • ✓A ficha da unidade preenchida (o cliente envia pelo /cadastro): EVO, grupo, planilha, professoras, dados da unidade, alertas.
  • ✓O servidor (VPS) contratado pelo cliente — Ubuntu, com o acesso SSH (IP + senha/chave) em mãos.
  • ✓A linha de WhatsApp do Studio disponível para escanear o QR (com alguém do lado do cliente para confirmar no celular).
  • ✓Os áudios das professoras e a chave da conta de serviço do Google (se for usar planilha).
Fase 1

Preparar o servidor

1.1 Acessar, ajustar fuso e atualizar

Conecte no servidor do cliente por SSH e deixe tudo em dia. O fuso de Brasília mantém os horários dos jobs certos.

no seu PC → servidor do cliente
# conecte no servidor (troque pelo IP do cliente)
ssh root@IP-DO-CLIENTE

# fuso de Brasília + atualizações + git
timedatectl set-timezone America/Sao_Paulo
apt update && apt upgrade -y
apt install -y git

1.2 Node 20 + ferramentas de build

servidor
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs build-essential python3
node -v   # deve mostrar v20.x

1.3 Tela virtual (Xvfb) + bibliotecas do navegador

O EVO (Angular) é instável em modo headless puro. A configuração validada roda com tela virtual (Xvfb). Instale o Xvfb e as libs do Chromium.

servidor
apt install -y xvfb \
  ca-certificates fonts-liberation libasound2t64 libatk-bridge2.0-0t64 \
  libatk1.0-0t64 libc6 libcairo2 libcups2t64 libdbus-1-3 libexpat1 \
  libfontconfig1 libgbm1 libglib2.0-0t64 libgtk-3-0t64 libnspr4 libnss3 \
  libpango-1.0-0 libx11-6 libxcomposite1 libxdamage1 libxext6 libxfixes3 \
  libxrandr2 libxkbcommon0 xdg-utils wget
Ubuntu mais antigo? Se algum pacote com sufixo t64 não for encontrado, instale a versão sem o sufixo (ex.: libasound2). Os nomes variam por versão do Ubuntu.
Fase 2

Instalar o robô

2.1 Clonar o código e instalar dependências

servidor
cd ~
git clone https://github.com/rrabadan86/SF-Chat_Experimental-Mensagens.git
cd SF-Chat_Experimental-Mensagens
git checkout main            # versao estavel (tudo mesclado)
cd Experimental
npm install                  # baixa o Chromium do Puppeteer (uns minutos)

2.2 Criar o .env a partir do modelo

Copie o modelo e preencha com os dados da ficha da unidade. É aqui que a unidade ganha a própria identidade — sem tocar em código.

servidor
cp .env.example .env
nano .env                    # preencha; salve com Ctrl+O, Enter, Ctrl+X
Os campos que mudam por unidade
STUDIO_NOMENome do Studio como aparece para a aluna. Ex.: Studio SlimFit Jardim Goiás.
EVO_URLUse https://evo5.w12app.com.br (o login acontece no evo5; o domínio seguro é capturado sozinho).
EVO_EMAIL / EVO_PASSWORDLogin do EVO da unidade.
EVO_EXPERIMENTAL_PATHTroque o número da filial no caminho pelo da unidade.
HEADLESSDeixe false — a instalação roda com Xvfb (tela virtual).
GRUPO_EQUIPENome exato do grupo da equipe no WhatsApp.
SHEETS_ID / SHEETS_ABA / GOOGLE_SA_KEYPlanilha de aniversários (ver passo 2.4).
NTFY_TOPICTópico exclusivo de alertas da unidade (nome secreto).
AUDIO_MAPJSON professora→arquivo de áudio (ver passo 2.3).
FORM_OUTBOX_TOKENToken secreto — o mesmo valor aqui e no formulário na Render.
O .env nunca vai para o GitHub (está no .gitignore). Ele fica só no servidor.

2.3 Colocar os áudios das professoras

Coloque os arquivos de áudio na pasta audios/ e ligue cada professora ao seu arquivo no AUDIO_MAP do .env. A chave é o nome da professora como aparece no EVO (minúsculo).

no seu PC → servidor
# envie os audios do seu PC para o servidor do cliente
scp *.ogg root@IP-DO-CLIENTE:~/SF-Chat_Experimental-Mensagens/Experimental/audios/

# no .env, mapeie professora -> arquivo (sem extensao):
# AUDIO_MAP={"ana":"A-Ana-Pos","carla":"A-Carla-Pos"}
Formato do áudio: nota de voz em .ogg (Opus). Se o cliente mandar MP3, converta antes com o mesmo comando que usamos na sua unidade (remove metadados que travam a reprodução).

2.4 Chave do Google + compartilhar a planilha

Só se a unidade usar a planilha de aniversários. Envie a chave da conta de serviço e compartilhe a planilha com o e-mail dela.

no seu PC → servidor
# envie a chave JSON da conta de servico
scp google-sa.json root@IP-DO-CLIENTE:~/SF-Chat_Experimental-Mensagens/Experimental/
Abra a planilha do cliente → Compartilhar → cole o e-mail da conta de serviço (está dentro do google-sa.json, campo client_email) como Editor. Sem isso, o robô lê mas não escreve.
Fase 3

Conectar e testar

3.1 Escanear o QR do WhatsApp da unidade

Rode a conexão inicial. Um QR aparece no terminal — quem estiver com o celular do Studio escaneia.

servidor
cd ~/SF-Chat_Experimental-Mensagens/Experimental
xvfb-run -a node src/run-now.js whatsapp
No celular do Studio: WhatsApp → Aparelhos conectados → Conectar um aparelho e aponte para o QR no terminal. Conectou? A sessão fica salva. Encerre com Ctrl+C.

3.2 Confirmar a linha dentro do grupo da equipe

Garanta que a linha do Studio (a que você acabou de conectar) está dentro do grupo da equipe — senão os avisos internos não saem. Confira também que o nome do grupo no .env bate exatamente.

3.3 Testar sem e com envio

servidor
# 1) so leitura do EVO (nao envia nada)
xvfb-run -a node src/run-now.js scrape

# 2) uma mensagem de teste para um numero seu
xvfb-run -a node src/run-now.js whatsapp 5562XXXXXXXXX 08:00 Teste

# 3) o job da manha inteiro, agora (envia de verdade!)
xvfb-run -a node src/run-now.js morning
Confirme: login no EVO ok, as experimentais aparecem na listagem, e a mensagem de teste chega no WhatsApp.

3.4 Configurar os alertas (ntfy)

O cliente instala o app ntfy (grátis) e se inscreve no tópico que você definiu no .env (NTFY_TOPIC). Faça um alerta de teste na frente dele.

servidor
# dispara um alerta de teste no topico da unidade
curl -d "Instalacao concluida — teste de alerta" ntfy.sh/SEU_NTFY_TOPIC
Fase 4

Deixar rodando 24/7

4.1 Subir com o PM2 (e voltar sozinho após reboot)

O agendador roda sob o PM2 via o wrapper scheduler-vps.sh (que já embrulha em xvfb-run).

servidor
npm install -g pm2
cd ~/SF-Chat_Experimental-Mensagens/Experimental

pm2 start ./scheduler-vps.sh --name slimfit-exp --interpreter bash --time
pm2 save
pm2 startup systemd -u root --hp /root
# ↑ copie e rode a linha que ele imprimir (registra no boot)

4.2 Verificação final

servidor
pm2 status                       # slimfit-exp = online
timedatectl                      # America/Sao_Paulo
pm2 logs slimfit-exp --lines 50  # sem erros
Deixe rodar até o próximo horário agendado e confirme no pm2 logs que o job disparou.
Fase 5

Formulário na nuvem (opcional)

Se você vender o agendamento online junto, publique o formulário na Render (é separado do servidor). Ele reusa o mesmo pacote de agendamento.

5.1 Criar o serviço na Render

  • ✓Crie um Web Service na Render apontando para o repositório do formulário.
  • ✓Comando de start (já usado): gunicorn app:app --workers 1 --timeout 120.

5.2 Variáveis de ambiente do formulário (na Render)

Environment · Render
EVO_URL / EVO_TOKEN / EVO_DNSAcesso do EVO da unidade para a API de agendamento.
ZEE_CONFIRM_TEMPLATEO texto da confirmação com o nome, endereço, mapa e persona da unidade (é aqui que personaliza a mensagem do formulário — sem editar código).
ZEE_STUDIO_PHONENúmero da recepção que recebe os alertas de turma lotada.
FORM_OUTBOX_TOKENO mesmo token do .env da VPS — é o que liga o formulário ao robô.

5.3 Ligar a ponte formulário → robô

No .env da VPS, aponte FORM_CLOUD_URL para o endereço da Render e use o mesmo FORM_OUTBOX_TOKEN. A ponte roda a cada minuto e puxa as marcações para a fila de envio.

Fase 6

Instagram — boas-vindas (opcional)

O Instagram trata o IP de servidor (datacenter) como robô e bloqueia. Por isso são duas peças, que resolvem coisas diferentes:

  • Cookies = QUEM você é (sessão já logada, sem digitar senha → não dispara 2FA/checkpoint).
  • Proxy residencial/móvel do Brasil = DE ONDE você acessa (um IP de "gente de verdade", não de datacenter).
⚠️ Sem o proxy, mandar DMs do servidor bloqueia a conta (aprendido na prática). Regra de ouro: proxy BR + volume baixo (IG_MAX_DIA=5, subindo aos poucos) + só seguidoras novas.

6.1 Exportar os cookies (no PC do cliente)

Num navegador logado no Instagram do Studio: instale a extensão Cookie-Editor (grátis), abra instagram.com, clique na extensão → Export → Export as JSON (copia para a área de transferência).

6.2 Colar os cookies no servidor

servidor
cd ~/SF-Chat_Experimental-Mensagens/Experimental
nano instagram-cookies.json   # cole o JSON, Ctrl+O, Enter, Ctrl+X

# confere se tem o sessionid
python3 -c "import json;d=json.load(open('instagram-cookies.json'));print(len(d),'cookies; sessionid?',any(c['name']=='sessionid' for c in d))"
Esse arquivo tem o sessionid (acesso à conta) — já está no .gitignore, nunca vai para o GitHub. Fica só no servidor.

6.3 Proxy residencial/móvel (Brasil)

Contrate um proxy móvel do Brasil (ex.: DataImpulse, ~US$ 5) no modo Fixo/sticky. Ele te dá host:porta:usuário:senha. Confirme que sai do Brasil e coloque no .env.

servidor
# testa o proxy (tem que dizer "Brazil")
curl -x "http://USUARIO:SENHA@HOST:PORTA" http://ip-api.com/json ; echo

# no .env:
IG_PROXY=HOST:PORTA
IG_PROXY_USER=USUARIO
IG_PROXY_PASS=SENHA
O robô já baixa sem imagens pelo proxy (economiza dados). 5 GB duram vários meses no nosso volume.

6.4 Testar leitura e um envio

servidor
# 1) so leitura (lista os seguidores)
HEADLESS=true node src/instagram-seguidores.js --user=usuario_do_studio

# 2) um envio de teste para um @ seu
xvfb-run -a node src/instagram-boasvindas.js --teste=seu_instagram
Leu os seguidores e a DM de teste chegou? Então a sessão e o IP estão ok. Se pedir login/checkpoint, os cookies expiraram (reexporte) ou o IP foi bloqueado (aí só proxy residencial resolve).

6.5 Ligar o job

No .env, ligue o Instagram e defina o perfil e o limite diário (o IG_PROXY já foi posto no 6.3). O job roda sozinho às 07:00 e só dá boas-vindas a quem passou a seguir.

.env
IG_ENABLED=true
IG_USERNAME=usuario_do_studio
IG_MAX_DIA=5
Reinicie com pm2 restart slimfit-exp. Os cookies expiram com o tempo — quando isso acontecer, o alerta no ntfy avisa e é só reexportar (passo 6.1/6.2).
